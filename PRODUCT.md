# Product

## Register

product

## Users

ALECO consumers using a mobile app on Android and iOS to view account information, submit service complaints, check hotlines, and track report status while away from staff tools.

## Product Purpose

Aleconnect Mobile gives consumers a direct service channel for reporting outages, power quality issues, meter concerns, service drop problems, pole hazards, referrals, and other account-related issues. Success means consumers can file a clear report quickly and receive a reference number they can track.

## Brand Personality

Reliable, direct, calm. The interface should feel like a utility service app: clear, official, and task-first.

## Anti-references

Not a marketing landing page, not a heavy staff dashboard, not an exact clone of any reference screenshot, and not decorative UI that slows down reporting.

## Design Principles

- Put report creation and status visibility first.
- Use clear category colors only where they improve scanning.
- Keep forms step-based so consumers do not face one long page.
- Prefer familiar mobile controls, readable labels, and obvious next actions.
- Require a verified Albay report location, Purok/Street and valid evidence; offer actionable recovery when location or photo permission is unavailable. Keep reporting drafts safe before navigating away.

## Accessibility & Inclusion

Use readable contrast, large tap targets, descriptive labels, and plain language for consumers filing reports under stress. By explicit product preference, app animations use full motion even when the operating system requests reduced motion. Keep hold-to-confirm timing and screen-reader actions independent of animation.

## Current consumer flows

Use five main destinations: Home, Reports, Advisories, Hotlines and Account. Guest access shows public All-target updates, service previews and hotlines; protected actions explain the sign-in requirement in one sheet. Account-number and linked-email sign-in remain consumer-only. Onboarding is not implemented in this release. Payment pages list external payment channels and never collect payment credentials.

Staff remains authoritative for account access, targeting, report statuses and editable fields. Optional unread/contact metadata must not become an authorization source. UI gating cannot substitute for server password/ownership/revision checks.
