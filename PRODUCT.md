# Product

## Register

product

## Users

ALECO consumers using a mobile app on Android and iOS to view account information, submit service complaints, check hotlines, and track report status while away from staff tools.

## Product Purpose

Aleconnect Mobile gives consumers a direct service channel for reporting outages, power quality issues, meter concerns, service drop problems, pole hazards, referrals, and other account-related issues. Success means consumers can file a clear report quickly and receive a reference number they can track.

## Brand Personality

Reliable, direct, calm. The interface should feel like a utility service app: clear, official, and task-first.

## Anti-references

Not a marketing landing page, not a heavy staff dashboard, not an exact clone of any reference screenshot, and not decorative UI that slows down reporting.

## Design Principles

- Put report creation and status visibility first.
- Use clear category colors only where they improve scanning.
- Keep forms step-based so consumers do not face one long page.
- Prefer familiar mobile controls, readable labels, and obvious next actions.
- Require a verified Albay report location, Purok/Street and valid evidence; offer actionable recovery when location or photo permission is unavailable. Keep reporting drafts safe before navigating away.

## Accessibility & Inclusion

Use readable contrast, large tap targets, descriptive labels, and plain language for consumers filing reports under stress. By explicit product preference, app animations use full motion even when the operating system requests reduced motion. Keep hold-to-confirm timing and screen-reader actions independent of animation.

## Current consumer flows

Use five main destinations: Home, Reports, Advisories, Hotlines and Account. Guest access shows public All-target updates, service previews and hotlines; protected actions explain the sign-in requirement in one sheet. Account-number and linked-email sign-in remain consumer-only. First-time visitors see three skippable welcome screens. Optional account setup is offered once per account on this device after interactive sign-in and any required password change; restored sessions bypass the introduction. Short PanelUI Tour chapters remain replayable from Help & support, with only public chapters available to guests. Billing inquiry and new-connection shortcuts open ALECO’s official website. Unsupported payment-channel pages are removed; old payment deep links return to Explore services.

Staff remains authoritative for account access, targeting, report statuses and editable fields. Optional unread/contact metadata must not become an authorization source. UI gating cannot substitute for server password/ownership/revision checks.

Under the version1 ticket-closure policy, resolved reports close through the first optional service rating, Staff closure or24hours. A remaining issue uses a new report; consumers cannot reopen a resolved report or start another follow-up. The existing appbar rating sheet remains optional, immutable and available once after closure. Only an accepted matching receipt can confirm successful delivery/closure.

Native Account setup requires a verified full-Albay offline map download before Finish; profile review remains optional and can proceed while the map downloads. Wi-Fi is the default and mobile data requires consent. Existing users retain available offline drafting and emergency access while setup is pending. Cached linked accounts and profiles permit drafting during transport failures, while fresh server authority is required to send. Preserve every saved report's original owner/account/revision, photos and receipt identity.
